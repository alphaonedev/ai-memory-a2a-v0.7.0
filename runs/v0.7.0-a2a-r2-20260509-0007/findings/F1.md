# F1 — Inheritance owner-check doesn't walk parent chain

**Status:** OPEN
**Severity:** P1 (functional gap)
**Round:** v0.7.0-a2a-r1 modernization (Round 2 prep)

## Symptom

When a parent namespace has `governance: {write: "owner", inherit: true}`
and a child namespace `parent/sub/deep` has no standard of its own, a
write to the child by the OWNER of the parent's standard returns
HTTP 403 with `"governance: owner-level action has no resolvable owner"`.

## Root cause (in v0.7.0 round-2-fixes @ dfb184f)

`src/db.rs::enforce_governance` calls `resolve_governance_policy(conn, namespace)`
to walk the chain leaf-first and pick up the parent's policy when the
child has none. That policy carries `write = Owner`. Good.

Same function then calls `namespace_owner(conn, namespace)` to fetch
the namespace_owner for the Owner-level check — but that helper only
looks at the EXACT namespace's standard memory, not the chain. With
no standard at `parent/sub/deep`, `namespace_owner` returns `None`
and `evaluate_level` denies with "no resolvable owner".

## Expected behavior

When a child inherits a policy via `resolve_governance_policy`, the
owner of the inherited policy's source namespace should also be carried
forward — i.e. `namespace_owner` should walk the same leaf-first chain
or `enforce_governance` should remember the namespace where the policy
was resolved from and look up the owner there.

## Repro

```bash
OPEN=ai:f1-test
PARENT=f1-parent
CHILD=f1-parent/sub/deep
SEED=$(curl -sS -X POST .../api/v1/memories -H "X-Agent-Id: $OPEN" \
       -d '{"namespace":"'$PARENT'","title":"_a","content":"a","tier":"long",...}' \
     | jq -r '.id')
curl -sS -X POST .../api/v1/namespaces/$PARENT/standard \
     -H "X-Agent-Id: $OPEN" \
     -d '{"id":"'$SEED'","governance":{"write":"owner","inherit":true}}'

# Owner write to child:
curl -sS -X POST .../api/v1/memories \
     -H "X-Agent-Id: $OPEN" \
     -d '{"namespace":"'$CHILD'","title":"o","content":"owner deep",...}'
# -> 403 governance: owner-level action has no resolvable owner
#    (expected: 201 — owner is the same as the parent's standard agent_id)
```

## Compensation

Scenario S60 was patched to write directly to the parent namespace (not
a deep child) so the test still validates the *cross-agent* enforcement
contract on a single-level policy. The deep-child inheritance check is
deferred to v0.7.1 with a follow-up patch on `namespace_owner` (walk the
chain) or `enforce_governance` (carry the resolved-from namespace).
