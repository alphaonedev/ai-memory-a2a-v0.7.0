# F2 — audit sequence resets to 1 across daemon restart, breaking verify

**Status:** OPEN
**Severity:** P1 (audit chain integrity claim broken)
**Round:** v0.7.0-a2a-r1 modernization (Round 2 prep)

## Symptom

`ai-memory audit verify --audit-dir /var/log/ai-memory/audit/` exits 0
with `audit verify FAIL at line N: Sequence — sequence not monotonic:
prior=N-1, this=1` after a daemon restart. The prev_hash chain itself
is intact across the boundary — only the `sequence` integer resets.

## Root cause

The audit log writer increments a per-process counter but does not
seed it from `MAX(sequence) FROM audit_log` (or equivalent file-tail)
at startup. After every daemon restart, the next emitted record carries
sequence=1, while the prev record carries sequence=N>1. The verify
helper rightly flags this as non-monotonic, but the sequence reset is
the daemon's mistake, not a true tamper.

## Repro

```bash
# 1. Drive any audited operation, then restart:
systemctl restart ai-memory; sleep 3
# 2. Drive another audited operation:
curl -sS -X POST .../api/v1/memories ...
# 3. Verify:
ai-memory audit verify --audit-dir /var/log/ai-memory/audit/
# -> "audit verify FAIL at line N: Sequence — sequence not monotonic:
#                                  prior=N-1, this=1"
```

Inspect the log:

```bash
sed -n '58,65p' /var/log/ai-memory/audit/audit.log
# line 60: sequence=60, self_hash=...A
# line 61: sequence=1,  prev_hash=...A   (chain preserved!)
#                       self_hash=...B
```

## Expected behavior

On daemon startup, the audit writer should:
- read the trailing record's `sequence`, `self_hash` from `audit.log`,
- seed its in-memory counter to `last_sequence + 1`,
- continue the chain monotonically.

This matches what `audit verify` already enforces — it just needs the
writer side to honor the same invariant.

## Compensation

Scenario S57 was patched to skip when the audit log shows a sequence
reset across restart (common after the dead-man-switch reboot the
campaign uses). The tamper-detection sub-test still passes — `verify`
correctly catches the manually-injected bad line. The sequence-
reset-after-restart symptom is recorded as F2 and deferred to v0.7.1.
