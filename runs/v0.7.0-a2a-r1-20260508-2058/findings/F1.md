# F1 — Federation NOT enabled on running daemons

**Severity:** P1 — blocks all cross-node replication scenarios
**Discovered:** 2026-05-08 during Round 1 wave-A smoke
**Affects:** every scenario that asserts on cross-node visibility (S1b, S2, S4, S13, S14, S15, S17, S40, S58, S59, S60, S62, etc.)

## Symptom

Direct write to openclaw via `POST /api/v1/memories` succeeds (200, returns id).
After 8s settle, hermes does NOT see the row in the same namespace.

```
$ ssh root@104.236.52.203 "curl -sS -X POST http://10.20.0.2:19077/api/v1/memories \
    -H 'Content-Type: application/json' -H 'X-Agent-Id: ai:test' \
    -d '{\"namespace\":\"smoke-test\",...}'"
{"agent_id":"ai:test","id":"65caed9c-...","namespace":"smoke-test","tier":"mid","title":"t1"}

$ sleep 3; ssh root@142.93.72.46 "curl -sS http://10.20.0.3:19077/api/v1/memories?namespace=smoke-test"
{"count":0,"memories":[]}
```

## Root cause

Federation config lives in TWO places and the daemon only reads CLI flags, not the config.toml `[federation]` section:

`/root/.config/ai-memory/config.toml` on both nodes contains:
```toml
[federation]
peers = ["http://10.20.0.3:19077"]
quorum_writes = 2
quorum_timeout_ms = 5000
```

But the systemd ExecStart line is:
```
ExecStart=/usr/local/bin/ai-memory serve --host 10.20.0.2 --port 19077 --db /var/lib/ai-memory/openclaw.db
```

No `--quorum-writes`, no `--quorum-peers`. Per `ai-memory serve --help`:
> --quorum-writes ... Default 0 = federation disabled, daemon behaves exactly like v0.6.0

The bootstrap manifest's `smoke_tests.peer_reach` only verifies `GET /api/v1/capabilities` succeeds (i.e. TCP reachability), NOT that writes fan out.

## Impact on Round 1

Every scenario that depends on writes from node-1 being visible on node-2 will fail with the same root cause. Expect ~30–40 scenarios to FAIL on this single defect rather than on individual feature bugs.

## Suggested remediation (operator-gated; NOT applied this round)

Either:
1. Update `/etc/systemd/system/ai-memory.service` ExecStart to add `--quorum-writes 2 --quorum-peers http://10.20.0.3:19077` (and the mirror on hermes) and `systemctl daemon-reload && systemctl restart ai-memory`.
2. Or fix the daemon to also read `[federation]` from config.toml (separate work item against ai-memory-mcp).

The brief prohibits both daemon restarts and SUT modifications during Round 1, so this finding is filed for operator action between rounds.
