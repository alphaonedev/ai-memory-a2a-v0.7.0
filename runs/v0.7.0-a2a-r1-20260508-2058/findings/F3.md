# F3 — `drive_agent.sh` not installed on v0.7.0-alpha droplets

**Severity:** P3 — affects 2 MCP-stdio scenarios only (S1, S27)
**Discovered:** 2026-05-08 during S1 wave-A run

## Symptom

```
$ ssh root@104.236.52.203 "ls /root/drive_agent.sh /etc/ai-memory-a2a/"
ls: cannot access '/root/drive_agent.sh': No such file or directory
ls: cannot access '/etc/ai-memory-a2a/': No such file or directory
```

S1 (`1_write_read_mcp.py`) and S27 (`27_openclaw_legacy.py`) drive memory writes through `bash /root/drive_agent.sh store ...`, which is the openclaw/hermes MCP-stdio shim. The bootstrap installs the ai-memory daemon but does NOT install the agent-runtime drive scripts that scenarios assume.

## Disposition

These two scenarios reclassified as SKIP for Round 1 (post-process step in `scripts/postprocess_round1.py`). The HTTP variant `1b_write_read_http.py` exercises the same product invariant via the `/api/v1/memories` endpoint, so coverage is preserved.

## Suggested remediation

Either:
1. Bootstrap should `scp scripts/drive_agent.sh` onto each droplet during setup.
2. Or the scenario should detect the absence and skip gracefully (currently it FAILs with 0 stores).
