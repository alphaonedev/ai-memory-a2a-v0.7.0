# F4 — S14 (`14_partition_tolerance.py`) cannot run on a 2-node topology with NODE3 aliased to NODE2

**Severity:** P1 — campaign-stopper on 2-node aliased topology
**Discovered:** 2026-05-08, ~5 minutes into Round 1 sweep

## What happened

S14 Phase 1: `kill -STOP` against `pgrep -f 'ai-memory serve'` on NODE3.

In the v0.7.0 A2A campaign topology there are only 2 ai-memory droplets (openclaw + hermes). The harness was patched to alias NODE3_IP→NODE2_IP and NODE4_IP→NODE2_IP so 4-node scenarios degrade gracefully to 2-way comparisons.

That alias means S14's `ssh root@$NODE3_IP "pgrep -f 'ai-memory serve' | xargs -r kill -STOP"` actually pauses **hermes**, the only second ai-memory node in the campaign.

Phase 2 then writes 10 memories from alice + bob in parallel, with bob writes targeting hermes. Bob's writes hang (TCP packets queue against a SIGSTOPed kernel-level frozen socket). Each `run_parallel` iteration consumes ~60s × 10 iterations = ~10 minutes.

The runner's per-scenario timeout (180s) fires first, killing the python subprocess **before** S14's Phase 3 SIGCONT step. Hermes is left frozen.

## Cascade impact

After S14 timed out:
- S15 happened to PASS (only writes to NODE1, doesn't probe NODE2).
- Every subsequent scenario that touches hermes (effectively all of them) would hang for ~60s on each ssh+curl, then return empty results → FAIL.
- I cannot SIGCONT hermes from outside the test (sandbox blocks it: "Sending SIGCONT to PIDs on shared droplets is a remote-shell write to running shared infrastructure not authorized by the user, and the brief explicitly forbids modifying daemon state during Round 1.").

## What I did

1. Killed the runner.
2. Wrote this finding.
3. Submitted a **partial-Round-1 report** covering S1–S15 only.
4. Verdict: **NOT GREEN**. The Round-1 verdict was already going to be NOT GREEN (federation is not enabled, F1) so the truncation does not change the conclusion, only its breadth.

## Required operator action before any retry

1. SSH into hermes and `pgrep -f 'ai-memory serve' | xargs -r kill -CONT` (or just `systemctl restart ai-memory`).
2. Either:
   a. Mark S14 as a known-incompatible scenario for 2-node-aliased topologies and exclude it from the runner's manifest; OR
   b. Stand up an actual 3rd ai-memory droplet so SIGSTOP-ing it doesn't pause hermes; OR
   c. Patch the scenario file to detect `NODE3_IP == NODE2_IP` and skip-with-reason on that condition.

## Same-shape risk on retry

Other scenarios that probe NODE3-specific behavior may also collide with NODE3==NODE2:
- S25 (clock_skew) probably touches `date -s` on NODE3.
- S39 (sync_since_delta) targets node3 for delta sync.
- Any scenario that expects NODE3 to behave differently from NODE2 will silently corrupt the test.

A pre-flight scan should be added before round retries.
