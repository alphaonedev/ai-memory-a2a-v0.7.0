# F2 — `/api/v1/links` schema diverged: scenarios send `from`/`to`, daemon expects `source_id`/`target_id`

**Severity:** P2 — affects every cross-agent link scenario
**Discovered:** 2026-05-08 during S52 wave-A run
**Affects:** S11 (link_integrity), S37 (get_links_bidirectional), S52 (a2a_link_signed), S57 (audit_chain_a2a), S65 (find_paths_a2a), S72 (age_a2a_kg)

## Symptom

```
POST /api/v1/links  body={"from": "M", "to": "N", "rel_type": "references"}
→ HTTP 422
   "Failed to deserialize the JSON body into the target type:
    missing field `source_id` at line 1 column 120"
```

The campaign's scenario authors wrote against the v0.6.x schema (`from`, `to`).
The v0.7.0 daemon under test expects `source_id`, `target_id`.

## Two possible interpretations

1. **v0.7.0 schema regression.** v0.6.x scenarios that previously passed against `from`/`to` now break — schema-breaking change without a documented compatibility shim.
2. **v0.7.0 deliberate rename, scenarios out of date.** The campaign was scaffolded from v0.6.4 sources without updating link bodies.

Either way, this round will fail every link-touching scenario with the same root cause.

## Suggested remediation (NOT applied this round)

Either:
1. Patch the scenarios (campaign-side change, allowed by the brief if the schema rename is intentional).
2. Add a backwards-compat shim in the daemon's `Link` struct: `#[serde(alias = "from", alias = "to")]`.

Filed for operator decision.
