# F3 — S70 scenario uses `ai-memory import` flags that don't exist in v0.7.0

**Severity:** P3 — campaign scenario bug, not a daemon defect
**Discovered:** 2026-05-09 during pgvector coverage-extension run
**Affects:** S70 (`70_pg_migration_roundtrip.py`)
**Status:** test-side bug; daemon behaviour unaffected

## Symptom

After pgvector 0.7.4 was installed on the postgres droplet (so the
prior `h.skip()` no longer triggers), S70 advances past the gate and
into Phase A — seeding 1000 rows into a fresh sqlite via
`ai-memory import`. Phase A reports:

```
seeded 0/1000 into /tmp/s70-seed-d065e1.sqlite
```

…and every subsequent phase trivially fails because the source file
has no rows.

## Root cause

`scenarios/70_pg_migration_roundtrip.py:58–62` invokes:

```python
cmd = (
    f"AI_MEMORY_STORE_URL=sqlite://{shlex.quote(sqlite_path)} "
    f"ai-memory import --format json --input /tmp/s70-seed.json --json"
)
```

But `ai-memory import --help` on the deployed v0.7.0 binary (commit
`e0d2086`) advertises:

```
Usage: ai-memory import [OPTIONS]
Options:
  --trust-source
  --db <DB>
  --json
  --agent-id <AGENT_ID>
  --db-passphrase-file <PATH>
  -h, --help
```

There is no `--format` and no `--input` flag. The CLI reads JSON from
**stdin** and writes to the file specified by `--db` (not by an
`AI_MEMORY_STORE_URL` environment variable). The scenario's invocation
errors out immediately with `error: unexpected argument '--format'
found` and the seed file is never created. The harness swallows the
error because `ssh_exec` returns non-zero rc but the scenario only
parses `imported` from JSON stdout, which on argparse failure is empty.

Verified directly on openclaw:

```
$ ssh root@104.236.52.203 \
    'cat /tmp/probe-seed.json | /usr/local/bin/ai-memory import --db /tmp/probe-seed.sqlite --json'
ai-memory: loaded config from /root/.config/ai-memory/config.toml
{"imported": 1, ...}
```

…proving the daemon-side import path itself is healthy; only the
scenario's CLI invocation is wrong.

## Suggested remediation (NOT applied this round per "no new code" rule)

Rewrite `_seed_local_sqlite` in `scenarios/70_pg_migration_roundtrip.py`
to pipe JSON via stdin and use `--db` instead of the dead env var:

```python
cmd = (
    f"cat /tmp/s70-seed.json "
    f"| ai-memory import --db {shlex.quote(sqlite_path)} --json"
)
```

This is a one-line scenario fix; out of scope for the current
"install pgvector + re-run" remit. Filing for a future campaign-repo
maintenance pass.

## Why this was hidden until now

In Round 1 + Round 2 the scenario short-circuited at the
`pg_available_extensions WHERE name='vector'` probe (lines 96–107) and
returned via `h.skip(...)` before ever invoking the broken import.
Installing pgvector 0.7.4 advances the scenario past that gate and
exposes the dormant CLI mismatch.
