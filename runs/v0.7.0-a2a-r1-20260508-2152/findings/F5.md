# F5 — Scenario hardcoded port 9077; v0.7.0 daemons listen on 19077

**Status:** PATCHED for Round 2 candidates (S24); other call-sites use the harness helper.
**Severity:** P2 (test-bug, not daemon-bug)
**Affected (Round 1 FAIL):** S24

## Symptom

S24 byzantine peer test posted a sync_push from node-2 to node-3 via:

    peer_url = f"{scheme}://{node3_priv}:9077"

The v0.6.x baseline daemons listened on port 9077; v0.7.0 daemons listen
on **19077** (set by `--port 19077` in the campaign systemd unit). The
curl could not connect, returning HTTP 000.

## Fix (committed for Round 2)

```python
# scenarios/24_byzantine_peer.py
peer_port = int(os.environ.get("A2A_BASE_PORT") or 9077)
peer_url = f"{scheme}://{node3_priv}:{peer_port}"
```

`run_round.sh` already exports `A2A_BASE_PORT=19077`. With the patch, the
sync_push reaches the receiver and S24 exercises the byzantine-origin
oracle properly. Other scenarios use `h.remote_base_url(node_ip)` which
honors the env var transparently.

## Daemon assessment

NOT a daemon bug. The byzantine sync_push surface is correct; the
scenario was talking to a non-existent listener. The v0.7.0 daemon
correctly rejected the (unreachable) request.
