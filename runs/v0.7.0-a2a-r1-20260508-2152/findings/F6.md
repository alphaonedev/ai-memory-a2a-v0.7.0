# F6 — v0.7.0 daemon endpoint/schema deltas vs. v0.6.x scenario baselines

**Status:** OPEN (test-bug, scenarios need v0.7.0 schema updates)
**Severity:** P2 (none of these block the v0.7.0 ship-gate; they block GREEN gate)
**Affected (Round 1 FAIL):** S43, S45, S46, S47, S48, S49, S52, S58, S63

## Pattern

Multiple scenarios were copy-pasted unchanged from the ai2ai-gate v0.6.x
baseline ("v0.7.0 A2A — copied from ai2ai-gate v0.6.4 baseline; runs
unchanged unless v0.7.0 schema delta noted"). The v0.7.0 daemon has
shifted endpoint shapes / schema versions / required fields that the
scenarios still expect at v0.6.x:

| Scenario | v0.6.x expectation               | v0.7.0 actual                                       |
|----------|-----------------------------------|------------------------------------------------------|
| S43      | `schema_version=="2"`             | `schema_version=="3"`                                |
| S45/S46  | `/api/v1/links` accepts old shape | 422 — needs canonical `source_id`/`target_id` shape  |
| S47      | `entity_register/get_by_alias` v1 | 404 — endpoint moved or alias-shape changed         |
| S48      | `check_duplicate` v1 body         | 422 — required field missing                         |
| S49      | promote/expire/restore/purge v1   | 404 — paths/methods changed                          |
| S52      | `/api/v1/links` (legacy)          | 422 — `source_id` required field                     |
| S58      | `/api/v1/notify` legacy body      | 422 — `target_agent_id` required field               |
| S63      | `consolidate` v1 body             | 422 — required field missing                         |

## Fix (out of scope for Path C topology bring-up)

Each scenario needs a one-time update to the v0.7.0 surface contract.
This is roughly 30–60 minutes of work per scenario times ~9 scenarios
= half a day. Path C's job was the topology bring-up, not the
scenario-content modernization. Files an item for a follow-up PR
("v0.7.0 scenario content refresh"), tracked separately.

## Daemon assessment

NOT a daemon bug. The v0.7.0 endpoints are deliberate: v0.6.3 -> v0.7.0
includes capability surface bump (schema_version=3), required-field
tightening on link/notify/consolidate, and lifecycle endpoint moves
(promote/expire/restore/purge). None of these are wire regressions —
they're intentional v0.7.0-alpha breaking changes.

## Patches already applied

- S43: schema_version check loosened to "schema_version >= 2" (so a v0.7.0
  daemon at sv=3 satisfies the v2-or-later contract). This makes S43
  evidence-positive on the next Round.
- S41: `_scrape` now uses `h.remote_base_url(ip)` (with target IP) so the
  metrics scrape hits the right peer, not 127.0.0.1.
- S40: `h.remote_base_url()` no-arg fallback now uses `node1_priv`
  instead of `127.0.0.1` (daemons bind to private VPC IP only).
- Harness `_local_addr_for(None)` defaults to `node1_priv:port`.
