## Topology — Track Q (4× GPU openclaw + 1× CPU postgres)

DO support approved 4 GPU droplets. Postgres stays on CPU SKU
(`s-4vcpu-16gb-amd`) since the account doesn't expose a 32 GiB CPU SKU
and asking for a 5th GPU just for postgres adds spend without
proportional cert benefit.

* 4× `gpu-4000adax1-20gb` **openclaw-{1,2,3,4}** at `10.20.0.{10,11,12,13}`
  - Autonomous tier: Ollama + gemma4:e4b (FP16) + nomic-embed-text-v1.5 + ms-marco-MiniLM cross-encoder
  - W=2/N=4 federation quorum (each peers with the other 3)
  - HTTPS+mTLS bilateral mesh (4 server + 4 client certs, ECDSA P-256, 10y)
* 1× `s-4vcpu-16gb-amd` **postgres** at `10.20.0.4`
  - PostgreSQL 16 + Apache AGE 1.5.0 + pgvector 0.7.4
  - Auto-tuned for 16 GiB host: shared_buffers=4GB, effective_cache_size=12GB,
    work_mem=32MB, maintenance_work_mem=1GB, max_connections=100,
    random_page_cost=1.1, effective_io_concurrency=200
  - Listen: localhost,10.20.0.4 (VPC-private only)
  - **Caveat:** 16 GiB postgres makes AGE bench-gate (S76) numbers
    storage/cache-bound rather than engine-bound. Cert correctness
    is unaffected (G2 fix verified separately); the bench-gate
    headline numbers will be conservative. v0.7.0.x can re-bench
    on a larger postgres if/when access lands.
* **Hourly:** $3.165/hr (4× $0.76 GPU + 1× $0.125 CPU)
* **Per cert pass (~18h):** ~$57 infra + ~$45 xAI = **~$102 standard**
  - +1.5× retry buffer: ~$153 (77% of $200 cap)
  - Worst case: ~$185 (~$15 margin)

This topology validates:

1. Autonomous-tier features running in production-correct conditions
   (gemma4:e4b on GPU, real LLM dispatch under load).
2. **Bilateral autonomous-tier federation** — all 4 peers run LLMs.
   This was infeasible on the prior CPU+single-GPU mixed-tier topology.
3. **W=2/N=4 quorum semantics** — partition tolerance, byzantine peer
   defense, replica convergence under concurrent LLM-bound writes.
4. AGE bench-gate (S76) with engine-bound (not storage-bound) numbers
   thanks to 32 GiB postgres RAM.
5. The full regression suite at autonomous-tier across the entire
   peer mesh (no `tier=semantic` skip rationale anywhere).
6. Three previously-skipped scenarios that need a distinct 3rd/4th
   daemon: S14 (partition tolerance), S25 (clock skew), S39 (delta-since
   under partition).

What this topology does NOT cover:

* Mixed-tier federation realism (production fleets with some
  autonomous-tier and some semantic-tier peers). Validated separately
  on the prior CPU campaign topology.
* Multi-GPU sharding inside a single openclaw daemon (single-GPU
  validates the v0.7.0 substrate; multi-GPU sharding is v0.7.1+).
* Cross-region federation latency (single-region nyc3 only).

**Recommendation: `gpu-4000adax1-20gb` for v0.7.0 cert.** 20GB VRAM is 2× headroom over autonomous-tier needs (Gemma 4B-class at FP16 ≈ 8-10GB + KV cache + nomic-embed + cross-encoder rerank). The third-party analysis correctly flagged two concerns at this SKU:

* **8 vCPU is the floor** for the cross-encoder rerank pool that v0.7.0 ships under Mutex. Throughput is bounded by core count; 8 is workable for cert testing but not for sustained production fleets.
* **32 GiB RAM is tight** for representative AGE bench-gate testing. Postgres `shared_buffers` + `effective_cache_size` want 16-24 GiB on a 32 GiB host to produce representative graph-engine numbers vs disk-I/O-bound noise. **Mitigation:** put the postgres + AGE DB on a dedicated `s-4vcpu-16gb-amd` (already provisioned) so the GPU droplet's RAM is reserved for the daemon + Ollama + cross-encoder pool. Bench-gate validity restored.

**Upgrade path (if 64 GiB matters):** swap the GPU droplet to `gpu-6000adax1-48gb` ($1.57/hr) — same 8 vCPU, doubled RAM, 48GB VRAM. ~$0.81/hr more per droplet; only meaningful if soak runs exceed 4h or AGE bench numbers come back storage-bound.

## Scenario family additions (autonomous tier specific)

New scenario IDs (under v0.7.0):

* **S86** — `auto_tag_quality_under_load.py` — store 100 memories, trigger
  auto_tag, assert ≥80% have ≥2 tags, no token-budget truncation visible
  (last-tag not cut mid-token).
* **S87** — `consolidate_dispatch_concurrency.py` — fire 5 simultaneous
  consolidate calls. No deadlock (all return within 60s); merged-row
  count is monotonic across replays.
* **S88** — `llm_rerank_vs_semantic_disagreement.py` — issue same query
  with `mode=semantic` then `mode=llm`. Quantify rank disagreement
  (Kendall tau / Jaccard@5). Floor: τ ≥ 0.3 (some disagreement is
  expected; full inversion is not).
* **S89** — `gpu_oom_graceful_degradation.py` — burst 50 concurrent
  LLM-bound calls. Daemon must EITHER queue cleanly (200s with
  observed latency) OR degrade to semantic-only (200s with
  `fallback=true` flag). Must not 500.
* **S90** — `nhi_discovery_autonomous_openclaw.py` — wraps NHI discovery
  driver with `tier_autonomous.md` overlay; runs against the GPU
  openclaw daemon for 30min; appends findings to run dir.
* **S91** — `nhi_discovery_autonomous_hermes.py` — same, hermes
  perspective.
* **S92** — `nhi_discovery_autonomous_a2a.py` — both NHI agents probe
  in parallel; cross-validates findings (consensus vs. flake).

## Gating dependencies

1. **G1/G2/G3 daemon fixes must land first.** No point running GPU cert
   over a postgres adapter that fails on `agent_quotas`, `find_paths`,
   or `verify_link`.
2. **HTTPS+mTLS deploy script update:** `scripts/deploy_wave4.sh`
   needs a `--tier autonomous` branch + Ollama health-check before
   daemon start (pin to `OLLAMA_HEALTH_TIMEOUT=120s`).
3. **NHI discovery layer wired:** runs against the new GPU topology
   transparently because the harness is tier-aware (no scenario-side
   changes).

## What is OUT of scope for this track

* Multi-GPU per node (4×GPU configs) — single-GPU autonomous-tier-full
  is sufficient for v0.7.0 cert. Multi-GPU sharding is v0.7.1.
* Production-load benchmarks (>1k req/s sustained) — spot-check perf
  is in scope; soak is its own track.
* Custom fine-tuned models — stock gemma3:4b is the canonical model
  for v0.7.0 autonomous tier.
